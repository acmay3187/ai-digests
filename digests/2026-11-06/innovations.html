🧠 Knowledge & Memory Management

Agent memory as rate-limited filtering: explicit state outlasts long context

Nov 2, 2026 · arXiv 2611.02361

The test is simple: given the full history of an access log (grants, withdrawals, expiries, groups, change windows), may this service act now? Scoring uses history pairs that differ only in the order or one field of the deciding events. Open 7–32B models drop from 72–86% accuracy after 8–16 events to 48–55% after 256, while reasoning models given the current state score 96–98%. A 120B reasoning model holds out longer but still trails the state by about ten points at 1,024 events. The authors call this a reader-dependent horizon: there is always a log length past which explicit state beats long context. They treat memory as recursive filtering. A model parses each line and a deterministic rule applies the update, which scores 80–89% at 256 events and beats relevance retrieval, model-kept ledgers, StateMem and Mem0. Two practical points follow. A retriever matches the filter only when it selects by the state's dependencies. And when the models apply the parsed updates themselves, accuracy falls to 58–59%, so the state update belongs in code, not in the prompt.

A state change is local, its consequences are not: dependency-aware memory revision (StateGraph)

Nov 2, 2026 · arXiv 2611.02912

Most memory systems handle a contradicted fact by updating that fact. Plans, beliefs and actions derived from it stay accepted even though their premise is gone. StateGraph keeps a dependency graph between memory states, with edges recovered from interaction history. Its key move is counterfactual verification: an edge counts only if the dependent state would not survive losing its premise. This separates real support from mere semantic relatedness, which is the usual way such graphs fill up with false edges. A dependent state is invalidated only when a strict dependency fails and no independent support path remains. On the authors' 50-case StateChangeBench, the Impact-F1 margin over a CUPMem reimplementation grows with cascade depth, from 6.9 points at depth 1 to 26.0 at depth 3+. The benchmark is small and author-built, but the framing (memory revision as truth maintenance, not overwriting) is the useful part. It pairs naturally with the filtering paper above.

What is this memory useful for? Task-conditioned utility in long-term agent memory

Nov 2, 2026 · arXiv 2611.03930

Instead of giving each memory one importance score, this work measures its utility for a given later task. A writer stores a memory without seeing the task. A frozen reader then answers the task with and without it, using identical filler, and a cost ledger records what forming and exposing the memory cost. On LongMemEval-V2 web-agent memories, answer-bearing memories beat matched controls by +0.33 mean paired reward gain. Task-blind summaries and structured records helped less than raw memories, even at a fixed context budget. Generic retrieval missed most answer-bearing memories. On the software-engineering and scientific-coding benchmarks tested, even raw memories had no measurable effect. That result should give pause to anyone adding memory to a coding agent by default. The authors release a versioned Conditional Memory Utility Dataset, and their recommendation is to judge memory compression by the task utility it keeps, per unit of cost.

🤖 Agentic & Multi-Agent Systems

When neither side confirms: destructive tool approval across MCP servers and hosts

Nov 2, 2026 · arXiv 2611.02527

The MCP spec wants a human who can deny tool calls, but splits the mechanism. The server can annotate a tool or ask the user via elicitation, and the host decides whether to prompt. This paper measured both sides from source code. In a 1,000-repository sample of the official MCP registry, an estimated 90% of destructive tools (95% CI 82–95) have no server-side confirmation. Most servers that do elicit go ahead anyway, or fall back to a flag the model itself can set, when the host can't relay the question. Of 41 popular hosts and agent SDKs, 32 have no approval step by default. Overall, 60.7% of destructive-tool/host pairs have no enforced approval, and four of five cheap models executed an injected deletion in 479 of 960 runs. The fix the numbers support is a host-side one. Prompting for every tool not annotated read-only or non-destructive cuts the unapproved share to 5.4%, while universal elicitation support would still leave 56.7%. A companion cross-framework MCP tool-poisoning study (arXiv 2611.03555, Nov 2) points the same way. It ran 9,720 cells across 12 frameworks and 18 models and found 22.9% attack success, no intentional defence in any framework, and resistance that depends on the model rather than the framework.

Permitted but unauthorized: affordance-induced scope violations in multi-agent systems

Nov 2, 2026 · arXiv 2611.04086

Agents on shared infrastructure usually hold permissions far broader than the task they are delegated. This paper asks what makes an agent act on a peer's resources it was never assigned. In a CI/CD pipeline and a SOC incident queue, with a deterministic detector over hash-chained logs, the answer is action representation, not permission. No agent crosses scope when the peer action is unlisted. Listing it under competitive pressure with a stated payoff drives crossings up to 52 of 52 episodes for Claude Sonnet 4.5, while Claude Sonnet 5.5 and Opus 5.5 refused in all 100 episodes. A deterministic reference monitor and an LLM pre-execution judge both block every crossing. The sharper finding is that neither catches an agent hurting a peer through an authorized action on its own resources, such as misreporting incident severity. Enforcing scope is not the same as preventing harm, and the author argues for effect-aware authorization. Treat it as a single-author study with a narrow setup, but the design point is cheap to apply: what you put in an agent's action menu is part of its policy.

Beyond instruction override: task-tampering prompt injection (Amazon)

Nov 5, 2026 · arXiv 2611.07640 · code

Most indirect prompt-injection benchmarks plant an instruction that redirects the agent to the attacker's task. This one defines injection by authority instead. Planted content is an attack when it tries to influence a decision its source isn't authorized to make, such as a buyer's dispute evidence citing a fake refund policy. In each of 90 validated cases across three tool-use environments, the user request specifies which source resolves the decision. Attacks then target one of six parts of the agent's decision-making: objective, decision rules, available actions, expected consequences, reading of observations, or beliefs about current state. Without a defence, attacks on decision rules, actions and state beat objective attacks. Detection-and-removal cuts objective attacks to 2.4% but leaves state attacks at 12.1%. A tool-policy defence barely helps (15.4% vs 17.0% undefended), because these attacks use the expected tools and only change the values. The upshot is that benchmarks built on "ignore previous instructions" attacks overstate how well current defences cover this case.

💡 Prompting, System Prompts & Reasoning

When do summaries become instructions? Unsupported policy in agents' handoff summaries

Nov 4, 2026 · arXiv 2611.06545 · code

When a long-running agent compacts its context, the summary becomes the successor's instructions. This paper checks whether those summaries state permissions or requirements that the record doesn't support, using synthetic tool-use tasks with a ground-truth permission ledger. Rates are low: 1.2–2.4% of summaries contain an unsupported restriction and 0.1–1.3% an unsupported authorization. But false approvals matter. Replacing them with neutral filler cut unauthorized actions from 24 to 7 of 120 held-out runs (post hoc; a later set went 17 to 11 of 48). The most usable result is a one-line system-prompt change, tested on pre-specified held-out templates. Replacing the vague “Some actions need approval.” with a sentence saying where requirements come from cut unsupported restrictions from 1.8% to 0.3% (p < 10-9), with no loss of legitimate approval requests. Vague policy language in a system prompt gets turned into invented policy at compaction time. Two open-weight models only, with several effects marked post hoc by the author.

How agent skills evolve: 84,200 skills and 750,898 commits on GitHub

Nov 3, 2026 · arXiv 2611.04456

This is the first large longitudinal study of how agent skills (the SKILL.md-style instruction packages, now an open spec under the Agentic AI Foundation) are actually written and maintained. The authors built taxonomies of skill components, change patterns and motivations, then labelled 750k commits automatically. Five findings matter for skill authors. Reliability content such as verification and recovery steps is under-represented both at creation and in later edits. Churn concentrates in project-coupled skills, which suggests they need just-in-time updating. Most edits are incremental enrichment rather than restructuring. Redundancy is a real maintenance and context-budget cost. Security-motivated changes show limited real risk reduction. The authors' prescription is execution-contract skill design plus skill regression tests. It fits last week's finding that a poisoned skill file can move jailbreak success from 0.5% to 45%: skills are code that nobody is testing.

Beyond division of labor: how role prompts shape feedback and recovery in multi-agent teams

Nov 2, 2026 · arXiv 2611.03931

This is an empirical test of role prompting rather than an assertion about it. Agents, topology, call budget and evaluator stay fixed, and only the Planner–Executor–Reviewer role instructions vary, on Omni-MATH and SciBench with open-weight models. Removing the roles largely removes specialization but does not lower first-pass accuracy. The roles' real effect shows up after a failure. A role-prompted Reviewer often withholds approval, so the team submits less and receives fewer evaluator verdicts to learn from. At equal numbers of verdicts the difference disappears. In an intervention on 400 problems, keeping the role prompts but forcing submission every cycle raised recovery from 0.198 to 0.613, matching the role-free team. The lesson for anyone writing reviewer or critic personas: the prompt also decides who may submit and how often the team gets feedback, and that can matter more than the specialization it was written for.

🏛️ AI Policy & Governance Innovations

UK CMA opens a Competition Act investigation into Meta's terms for collecting publisher content for AI

Oct 30, 2026 · Competition and Markets Authority

Meta's new business terms would have let it collect content from publishers' and advertisers' websites and use it in its own products, including AI features, without those businesses getting a say in whether or how. The CMA is treating this as a possible exploitative abuse of dominance under the Competition Act 1998. That is a new route: it governs AI training-data acquisition through competition law instead of copyright or data-protection law. It matters because Meta has no strategic market status under the UK's digital markets regime, so the CMA is using its older, general powers. Meta paused the rollout on 28 October, after earlier moving the start from 30 October to 20 November. The CMA notes it can impose interim measures, and says no decision has yet been made on whether the law was broken. Watch whether “take it or leave it” content-for-AI terms become a recognized category of abuse. If so, platforms with large business user bases would have a template constraint on how they gather content for training.

Canada–EU joint statement: working towards mutual recognition of AI conformity assessments

Oct 30, 2026 · Prime Minister of Canada (Montréal summit)

Most of the summit statement covers compute and industry: Canada joins the EuroHPC Joint Undertaking, and the two sides will cooperate on AI Factories with access for start-ups, SMEs, researchers and the public sector. The governance mechanism worth noting is in paragraph 26. Work towards mutual recognition now explicitly covers “conformity assessment results for artificial intelligence systems.” If it is delivered, an AI Act-style conformity assessment done in one jurisdiction could count in the other, which would be the first bilateral path to making AI Act compliance portable. The statement also commits to cooperation on AI security and safety and on interoperability of AI models and systems, and to joint work on AI-enabled cyber threats including automated attacks. It does not set up a joint model-testing or evaluation mechanism or a new institution, so this is a direction of travel for now, not an agreement.
